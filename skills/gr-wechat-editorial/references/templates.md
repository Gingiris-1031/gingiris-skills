# 工作表与交付格式

## 文章简报

账号/作者：
读者与本篇要解决的问题：
交付阶段：本地 / 草稿箱 / 已明确授权的正式发布
已有系列与本次新角度：
当前文风样本/规范：
可用素材与不可公开范围：
标题、摘要、署名：
封面/正文图及使用权限：
CTA（可为空）：
内容审核人 / 终审人 / 发布负责人：

## 来源表

| 稿件位置 | 事实/引语/观点 | 原文路径或公开 URL | 时间码/页码 | 发言人 | 时间与统计口径 | 证据类型 | 可公开范围/处理 |
|---|---|---|---|---|---|---|---|

原始来源保留在作者授权的存储位置，公开发布包不包含私有会议全文。数字有冲突时加“待核/采用哪一口径及原因”。无法确认的发言人不署名引用。自己的新判断注明是分析，不强造引用。

## 审稿报告

版本：
内容审：通过 / 修改后复审 / 缺证据
阻断问题：原句、原因、需要的证据或可替换措辞
风格建议：原句、建议、是否已采纳
终审：通过 / 待预览 / 需修改
手机/后台预览：完成情况与证据

## 本地交付 JSON

```json
{
  "title": "一次用户访谈如何转成团队能执行的修改",
  "author": "作者名",
  "digest": "说明真实问题、证据与交付步骤。",
  "content": "<p style=\"line-height:1.8;margin-bottom:1.2em;\">已审核的正文。</p>",
  "content_source_url": "",
  "thumb_media_id": ""
}
```

必填 title/content；其他是本地交付元数据。thumb_media_id 为空表示尚未上传封面，不能称为 API 可直接提交。未知字段报错，防止把密钥、内部审稿字段误放进公开包。本地打包器创建全新目录，输出 article.html、article.json、manifest.json，不覆盖已有目录。

## 交付台账

| 版本 | 账号 | 来源卡 | 本地包 | 内容审 | 终审 | 草稿ID | 创建/更新时间 | 回读结果 | 发布URL及验证时间 | 群发状态 |
|---|---|---|---|---|---|---|---|---|---|---|

草稿创建后超时：先查后台同标题/版本及已保存 ID。若存在则回读，若仍不明则交接人工排查。未经确认不能当失败重建。发布后的修订以新版本记录，避免覆盖旧证据。
