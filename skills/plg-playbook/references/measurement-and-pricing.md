# Measurement coverage and pricing acceptance

## Verify collection before interpreting conversion

Use when activation metrics are missing or a product spans Web and CLI. For each surface define the start event, successful core task, repeat-use event and paid event using the actual product's value. Then record:

`Surface | Event definition | Source | Test event and observed result | Internal-user exclusion | Cohort dates | Identity / join coverage | Missing data`

Test that events arrive, are not duplicated on retries and represent success rather than a click or login. Report denominators and observation windows. Keep Web and CLI cohorts separate unless a reliable, permission-appropriate identity link exists. A measured Web funnel does not establish CLI retention. Missing telemetry is unavailable, not zero; do not infer activation from stars, downloads or impressions. This does not require mandatory registration for all open-source CLIs.

## Match pricing promises to a working product

`Tier promise | User-understandable billing unit | Included usage | Overage behavior | Implemented capability | Acceptance evidence | Publish / revise / defer`

Check the target task against the combined limits. State what happens at the limit; do not copy a competitor's package without checking buyer needs. Test every advertised capability in its tier. Omit or clearly label unavailable features rather than selling a present-tense promise. A small interview sample can expose confusion but does not establish a market-wide price or conversion benchmark.
