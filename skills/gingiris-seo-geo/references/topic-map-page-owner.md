# Topic Map 与 Page Owner 决策框架

> 用于新站规划、新词选题、站点结构改造、页面蚇食排查和工具页优化。框架参考 Bysocket《AI 工具站 SEO 小册子》的 Entity / Topic Map / Keyword-to-Page / Last-Click 思路，并结合 Gingiris 对 Page Owner、证据等级与发布验收的现有规则。

## 1. 先画边界，再查词

用四句话定义站点 Entity：

1. 我们是什么？
2. 我们提供什么可用能力？
3. 我们服务谁、帮他们完成什么任务？
4. 什么看起来相关，但明确不覆盖？

第 4 句是防止 Topic Map 被流量诱惑带偏的门禁。

## 2. 搜索 ICP 不是人口学画像

每个主题记录：

- 搜索者角色/场景；
- 当下要完成的任务；
- 主要意图（信息/导航/商业/交易）；
- 他需要哪些证据才能决策；
- 页面上合理的下一步（使用、下载、注册、试用、联系或继续学习）。

## 3. Topic Map 的数据来源

外部来源表达“人们在公开搜什么”：GSC 真实查询、SERP / PAA / Related Searches、当前关键词工具、竞品页面与公开社区。

内部来源表达“人们为什么买或不买”：产品文档、站内搜索、客服工单、用户访谈、售前/演示、退订与流失原因、经过脱敏的一手案例。

先用品牌相关度、商业价值和词簇流量潜力评估主题，再深挖关键词。未当前核验的 Volume / KD / Traffic Potential 一律写“待验证”。

## 4. Keyword Cluster 与唯一 Page Owner

一个 Page Owner 对应：

- 一个明确主意图；
- 一个 Top Keyword；
- 一组同任务的次要词/问题词；
- 一个 canonical URL。

不是“一词一页”。判断词是否合并，先比较目标市场 SERP Top 10 的 URL 重合、页面类型与主任务。只有当细分需求已形成独立 SERP，且新页能提供不同功能/证据/结果，而不是只换 Title 时，才新建子页。

## 5. SERP Research 的必交付物

写作前记录：

| 字段 | 答案 |
|---|---|
| 主要意图 | 用户要完成的任务 |
| Content Type | Tool / Feature / Solution / Blog / Collection / Other |
| Content Format | How-to / List / Review / Comparison / Alternatives / Other |
| Content Angle | 仅记录当前 SERP 真实出现且页面能支撑的 angle |
| 必须交付的组件 | 工具、步骤、表格、评测方法、截图、限制或其他 |
| 内容缺口 | 现有前排页面没有解决的问题 |
| 建议处置 | 优化旧 Page Owner / 新建 / 不做 |

## 6. 工具页先交付结果

工具意图的页面，Hero 优先放可操作功能和结果路径，而不是几屏 SEO 文案。可按需加 Templates、Use Cases、真实 How-to、Features、Pricing、Testimonials、FAQ、Explore More 和 CTA；没有真实能力/证据的模块必须省略。

## 7. 内链是阅读地图，不是配额

- 下行：频道/支柱页 → 相关子页；
- 上行：教程/证据页 → Page Owner / Money Page；
- 水平：同任务中真正需要的相关页。

anchor 说清目标页要完成的任务。不用固定数量、不把页脚链接堆叠当作主题权重。

## 8. 验收从发布状态到真实结果

分开记录：草稿完成 → 已落库 → 已提交 → 已部署 → 线上验证 → 已在 sitemap → 已抓取 → 已进 GSC → 有查询曝光 → 有点击 → 有真实转化/可复核 AI 引用。

新页前期按目录看新增非品牌词页、词覆盖、曝光、点击和 CTA 任务完成；不因单日或小样本排名波动反复改 Title/Meta。
